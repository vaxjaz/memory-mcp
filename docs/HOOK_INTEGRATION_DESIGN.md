# 基于宿主 hooks 的无侵入记忆接入设计

状态：长期设计稿。0.1.3-rc.1 已实现 ZCode 的 hook、setup、doctor、显式项目绑定及一次 Stop 宿主整理请求，见 [候选实现与验收](ZCODE_HOOKS.md)。本文其他宿主、自动 Git 身份路由等仍未实现；文中的第一阶段“不使用 Stop 续跑”已由本候选的一次受限继续执行实验取代，不能视为当前行为保证。
文档核对日期：2026-10-29。文档支持、配置生成、事件实测、真实使用效果分别验收。

## 目标与范围

安装一次，在宿主正常工作过程中触发记忆流程。项目中不新增或修改 AGENTS.md、
CLAUDE.md、rules、hook 脚本等文件；跨项目使用用户级配置和本地项目注册表。
继续复用宿主模型，不内置模型、不调用额外模型 API、不依赖后台模型服务。

hook 负责采集和调度，MCP 负责宿主主动查询与写入，二者调用同一个记忆核心。
自动发生事件不等于自动理解正确；触发可靠性和学习质量需要分开测量。

用户约束来自安装实测反馈：日常无需显式触发，不侵入项目 AGENTS.md。
这不是“后台无限记录一切”或“每轮生成一条偏好”的要求。

## 架构

```text
宿主会话事件
    │
用户级 hook / 插件配置
    │
宿主适配器：输入解析、能力声明、输出编码
    │
项目与会话路由
    │
共用 MemoryService ───────── SQLite
    │                         ├ 原始事件与来源
    │                         ├ 决策案例与产物引用
    │                         ├ 偏好假设与反例
    │                         └ 交付、复查与处理状态
    │
有限上下文 → 宿主模型 → 已有 MCP 工具 → 案例 / 假设修订
```

同一个可执行程序计划提供三个入口：

- `serve`：现有 MCP stdio 服务。
- `hook --host <name>`：接收一次宿主事件，执行本地操作，输出该宿主支持的响应。
- `setup` / `doctor`：用户级接入配置、回滚、状态检查；具体参数在实现时确定。

hook 可以直接调用共用核心，不必每次额外建立 MCP 会话。
事件处理不启动第二个模型；语义解释仍由正在工作的宿主模型完成。
MCP 工具不要求宿主具有 hook 能力，保留独立使用方式。

## 先按能力适配，再按事件名映射

不假设大小写相同的事件就有相同语义。每个适配器分别声明：

1. 能否收到会话开始、用户输入、工具完成、回合结束和压缩事件。
2. 哪些事件允许向下一次模型请求追加上下文。
3. 是否有实际用户输入、回复、工具标识、会话 ID 和工作目录。
4. 是否支持宿主原生的模型处理 hook；是否会额外消耗模型调用。

最后一项不是第一版的依赖：普通命令 hook 没有可直接调用宿主模型的对象。
CLI、IDE、桌面版、云端版及具体版本分开记录，不由产品名推定支持程度。

| 宿主 | 官方资料提供的接入基础 | 本设计的处理 |
| --- | --- | --- |
| Codex | 用户级 hooks；会话、输入等事件；部分事件支持模型上下文；存在 hook 信任流程 | 用户级安装，保留宿主审阅机制，适配已验证事件 |
| Claude Code | 生命周期 hooks；输入事件可附加上下文 | 单独解析事件和输出，不将 JSON 形似视作完整兼容 |
| Qoder CLI | 文档包含会话、输入和工具事件，以及上下文输出说明 | CLI 与 IDE / QoderWork 分别验证 |
| ZCode | 用户配置 / 插件 hooks；输入和会话事件可提供上下文；命令 hook 无模型调用对象 | 适配 process 配置，按宿主限制输出 |
| Cursor | 用户级 hooks；sessionStart 可注入上下文；beforeSubmitPrompt 的文档输出为放行 / 阻止 | 输入事件可采集；不向它写未支持的上下文字段，使用其他已验证注入点 |

这张表是文档核对，不代表已经完成这些客户端的安装和实测。
无可用上下文注入点时明确降级为采集 / 手动查询，不宣称完整无感使用。

## 事件与工作流

| 内部事件 | 本地处理 | 需要宿主模型处理的部分 |
| --- | --- | --- |
| 会话开始 / 恢复 | 路由项目、绑定会话、提供短接入说明与待复查索引 | 按当前任务读取所需案例，不要求重新阅读全部历史 |
| 用户输入 | 保存可见原文及来源；根据已知项目生成有上限的候选材料 | 判断相关性、是否存在有价值的反馈或决策问题 |
| 工具完成 | 保存必要的产物定位与处理进度；识别本系统自己的工具调用 | 实际结果如何影响当前判断 |
| 回合结束 | 完成本轮已收集事件落盘，保留未处理索引 | 不在普通 Stop hook 中虚构一次模型提炼 |
| 上下文压缩 | 保留原始材料与处理游标；在支持的后续注入点提供索引 | 需要时回查原文，而不是反复压缩旧摘要 |

默认不接管工具权限、不修改工具输入、不阻止用户任务。
第一阶段不使用 Stop 的阻止 / 继续能力强迫模型再次运行，以免记忆操作形成循环。
未形成案例的材料留待后续合适时机处理，不把本轮完成标记当作用户认可。

### 一次实际协作

1. 宿主触发开始事件，本机路由到项目 A。
2. 用户提交任务；hook 保存本次收到的原文，提供有限的候选来源与读取入口。
3. 宿主正常解决任务，可以调用 memory_search / memory_read 调查已有案例和反例。
4. 用户评价实际方案；新原文入库。宿主结合它看见的方案与产物判断是否值得整理案例。
5. 形成案例或假设时，通过 MCP 保存解释与来源，不覆盖原始事件。
6. Stop 只完成本地记录。新反馈与旧假设冲突时，按现有修订机制进入复查。

## 原始事件不等于偏好记忆

在现有案例 / 假设之外增加原始事件层，避免所有输入都出现在偏好检索中。

- 原始事件：宿主实际交付的内容、来源、事件类型、会话与项目定位，不加入偏好结论。
- 决策案例：关联用户评价、当时方案、产物和结果。解释自由表达，可没有结论。
- 假设：宿主产生的可质疑解释，保留支持、反例和适用条件。

结构只追踪交付与来源，不校验“用户究竟是什么意思”。事件格式规范化不能改写原话。
宿主没有交付的回复或上下文标为缺失，禁止将零散引文包装成完整决策案例。

安装时明确采集范围：第一阶段仅保存 hook 实际提供的用户文本及必要定位信息。
最终回复仅在宿主明确提供时采集；不自动复制附件、全部工具输出或追读整份历史日志。
需要读取宿主 transcript 的功能单独启用，按宿主和日志格式验证，不作为基础接入条件。
敏感材料可关闭正文采集；诊断日志默认不输出聊天正文。

未来需要给宿主提供读取原始事件的工具或资源入口，并允许案例链接这些事件。
不将原始事件偷偷转换为 model_inference，也不在自动采集时生成统一“用户画像”。

## 项目自动识别与路由

优先级：

1. 用户级项目注册表中的显式绑定，以及当前会话已确认的项目选择。
2. 宿主实际提供的当前工作目录与已知注册项目匹配。
3. Git 仓库身份；将 HTTPS / SSH 地址、`.git` 后缀等归一化，移除凭据。
4. 无 Git 时为规范化目录分配本机项目 ID，保存于记忆数据目录。

注册表保存在用户记忆目录，不写入项目。现有 `project:vax-plan`、
`project:memory-mcp` 通过显式别名绑定保留，不因引入新识别方法而丢失。

- 同一仓库的不同 worktree 默认关联同项目，分支仍作为案例语境保留。
- 同名、不同 owner 的仓库不得合并；fork、镜像、多个 remote 不自动认定为同项目。
- monorepo 的子项目可在用户注册表单独绑定。
- 多工作区或对话中切换项目时，不仅凭进程启动目录作结论；允许宿主明确切换会话范围。
- 缺少路径且没有已确认绑定时，保持未解析状态；不默认为 global，也不混入上次项目。
- 个人通用偏好仍需单独形成依据，不把项目案例自动提升为 global。

不能完全自动处理的歧义可以询问一次并保存绑定，不在每条消息重复询问。

## 上下文交付

一次输出分成两部分：

- 很短的系统操作说明：当前 scope、可用记忆入口、哪些内容需要复查。
- 明确标为不可信资料的候选内容：案例 ID、有限原文片段、来源、反例入口。

不直接注入所有记忆，也不把假设转换为强制用户要求。
宿主的上下文角色和字段由适配器处理；记忆正文即使经由 developer context 交付，
也只能作为被引用的资料，不能拼接成执行指令。
分隔和标注无法完全消除模型误读，仍需用包含指令诱导内容的案例进行验证。

检索起步使用本地关键词候选与显式关联，允许宿主进一步调用 MCP 改写查询。
没有 embedding 或独立模型时，不声称已经实现语义相关性判断。
无匹配时可以只给入口，不拿不相关的近期偏好填满上下文。
每条反馈不是一条必须立刻提炼的偏好；每轮也不强制询问用户。

候选交付应有条数与总长度上限。起步目标可设为至多 3 个案例、约 1500 字符；
这是实验参数而非已验证的最优值，需要同时统计遗漏与干扰。

## 并发、去重与失败行为

- 按宿主、安装实例、会话、宿主事件 ID / 序号处理重投，避免重复生成案例。
- 宿主没有稳定 ID 时，仅凭相同正文无法可靠去重；连续两次相同回答不能直接合并。
  保留事件，标记可能重复，不能靠内容哈希丢掉真实发言。
- 区分根会话、子 Agent、父会话和原始发言来源；模型引用用户旧话不是新的用户证据。
- 对本系统 memory 工具的 PostToolUse 事件不再次做记忆推断，防止自触发。
- 不在 hook 中递归调用宿主或 MCP 自身，不强制续跑 Stop。
- 仍使用 SQLite 事务与版本冲突检查；多个客户端写同一个项目时不静默覆盖。
- 超时、数据库锁或输入格式不兼容时返回宿主认可的空响应，继续正常工作。
  错误可在 doctor 中检查，不能把记忆故障变成业务任务的阻断。

交互路径不做全量重蒸馏或大范围索引。初步以正常触发耗时 P95 小于 500ms 为目标，
需要逐平台测量；宿主进程启动开销与本程序耗时分开记录。慢操作可延后做本地处理，
但不假设后台有模型可完成语义解释。

## 安装、卸载与自检

计划由 setup 发现已安装宿主，生成或合并用户级 hook 配置：

1. 显示目标宿主、可执行路径、数据位置、配置变更和采集范围。
2. 备份原配置，仅增加本程序拥有的项，不覆盖已有 hook。
3. 用本机绝对路径调用同一个二进制，不要求用户安装 Python / Node。
4. 保留宿主自身的信任 / 启用步骤，不绕过审阅；配置存在不代表 hook 已执行。
5. 需要重启或新会话的宿主明确提示，不能假设热加载。

doctor 至少区分：程序可执行、MCP 可连接、hook 已配置、hook 已启用 / 信任、
实际事件已收到、上下文已交付、宿主已使用材料。这些不能统一显示成一个“安装成功”。
若宿主没有交付确认信号，就将“模型已读取”标为未知，不能由写入 stdout 推定。
诊断显示最近事件、scope、处理结果和延迟；查看正文需要显式读取资料。

卸载仅移除本程序拥有的配置项，恢复或保留其他 hook。数据库默认保留，另行显式删除。
只支持远程 MCP 或不执行用户级 hooks 的环境，明确报告当前能力不足。
云端事件在云端执行时，数据也在云端；不会借用户级安装自动同步到 VPS 或桌面。

## 第一阶段实施与验收

先打通一个真实宿主的完整链路，再扩大适配，不同时宣称全部客户端已支持。

1. 共用核心增加原始事件、会话路由、项目注册表和有上限的上下文构建。
2. 实现 Codex 适配，保留宿主信任流程，在真实新会话中确认事件输入和上下文交付。
3. 用相同核心扩展 Claude Code、Qoder、ZCode，分别保存脱敏事件样本和兼容版本。
4. Cursor 按实际注入点实现降级路径，不向输入事件硬塞未支持字段。

验收至少覆盖：

- 安装、运行、更新和卸载均不修改项目文件，项目 git status 前后可核对。
- 重启、恢复、切换项目、worktree 和多客户端不会路由串项目。
- 原文保持一致；旧案例能回查原始事件；采集缺口明确暴露。
- 重复交付、并发、Stop、子 Agent 和自身工具事件不造成循环或证据重复计数。
- hook 超时或数据库不可用时，宿主仍可继续完成正常任务。
- 无模型 / 额外模型密钥也能完成采集、路由与候选交付。
- 事件接收率、候选交付率与模型实际使用率分开记录；使用后返工与错误迁移单独评估。

能力等级按“文档支持 → 配置可生成 → 原始事件实测 → 上下文交付实测 → 任务效果”
逐级标记。测试通过的是触发和数据路径，不能据此确认偏好学习已提高质量。
