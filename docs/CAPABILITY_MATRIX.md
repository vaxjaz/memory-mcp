# memory-mcp 能力矩阵

版本：0.6.4，提交 `8e19808`（分支 `release/0.6.4-rc`）。本机安装的是由该提交构建的正式包。验证环境：Windows，Go 1.26.11，ZCode 3.16.3（本机真实客户端）。验证日期：2026-11-24。

这份文档回答一个问题：**这个工具对使用者承诺什么，每一条承诺现在是否成立。** 它是改动的依据：先改这里，再改代码；每一格都必须有证据，没有证据的标“未验证”。

**本轮范围：ZCode。** Codex 的能力补齐和原生验收由 Codex 那一边自测；Qoder 另开一轮。

## 缺口归类

上一版把 12 个不成立项归为六类，每一类当作一个整体来解决：

1. **触发面没有定义** → 一个配置文件，路径以项目根为准，字段各自独立并给出原因，数组入参可映射，被跳过的调用留痕。第 1、2 节和诊断里的相关项已全部成立。
2. **写入前比对触发过宽** → 只认三种关系：同一条证据、同一个入口词、正文重合过半。
3. **清理模块不可自学** → 报错一句话说清缺什么和下一步，每个参数都有说明。
4. **诊断有盲区** → 跳过有痕迹，原因有名字，hook 与服务不是同一个程序时能发现。
5. **文档和术语没有单一来源** → 示例即测试，接口文档与程序逐项核对，命令和工具都有文档，术语统一。
6. **验收没有统一入口** → 一条命令跑完，并且关卡不能自己把自己算成通过。

剩下的一个不成立项（搜索工具的文件名过滤参数）和四个未验证项（绑定项目里的完整一轮、两个客户端共用一个库、Qoder 两个适配器的原生执行）都有明确的归属。

## W(x) 与 R(x) 的目标定义

这一轮的核心是两个服务端函数。其余工作（清理模块的说明、文档、验收入口）是为它们配套的。

分工原则：**门槛用身份，检索用词。** W 是门槛，只在有把握时拦；R 的检索容许噪音，由宿主判断。

### W(x) 写入判断

一条新经验进来时，工具输出三种结果之一：直接写入、要求比对（附候选）、拒绝（附原因）。

| 不可触发的规则 | 写入时拒绝，并给出这个项目可用的工具和字段；`doctor` 列出库里已有的这类规则 | 已实现，真实库零误判 |

## 写入前比对的数据

对真实库 24 条经验做只读统计，不同触发规则下的结果：

| 规则 | 会被要求比对的记录 | 相连的记录对 |
| --- | --- | --- |
| 以前：共用词出现 3 次，重复计数 | 23 / 24 | 271 |
| 共用 3 个不同的词 | 23 / 24 | 246 |
| 3 个不同的词，且每个词至多出现在 10% 的记录里 | 13 / 24 | 22 |
| 3 个不同的词，且每个词至多出现在 20% 的记录里 | 20 / 24 | 68 |
| **采用：共用证据或共用入口词，或正文重合过半** | **4 / 24** | **4** |

记录对按有向计，A 对 B 和 B 对 A 各算一次。把这个库里的记录连在一起的最常见词是“隔离”“回放”“同一”“返回”，都是叙述用词。

逐对核对的结果：

- **旧规则连起来的记录多数毫无关系。** 例如《递归 cue 引入后只通过 Go 测试仍可能导致 MCP 无法启动》和《Windows junction 可能绕过常规路径归属判断》，只因共用了“windows”“同一”“通过”就被要求比对。
- **按少见词卡严也不解决问题。** 严口径留下 7 对，其中 6 对是两字碎片碰巧相同。只有 1 对算相关。
- **只认证据和入口词时留下 4 对，全部相关。** 例如《业务观察序列化后短反例字段丢失》和《新增 cue 前提后旧业务观察缓存可能绕过条件》共用了入口词 `ObservedBusinessMatches`。
- **正文重合比例能区分“重写同一条”和“两条不同的经验”。** 这个库里任意两条经验的正文重合比例最高只有 13%；同一条事实换个说法重写，重合比例是 71%。

**采用的定义。** 写入前比对在以下三种情况之一发生：引用了同一条证据；用了同一个入口词；两段正文共有的词占到两者全部不同词的一半以上。不再因为共用了几个词就比对。代价是：换了证据、换了入口词、重述后重合又不到一半的同一条经验不会被拦下，会多出一条重复记录，之后由清理流程合并。
