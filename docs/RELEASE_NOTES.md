# 0.3.0-rc.1（试用包，未正式 Release）

默认辅助模式：服务级持久配置作用于全部绑定项目，显示模式但不逐轮询问。保留每轮短提醒，默认不采集原文、不查库、不造检查状态、不装行动门禁或 Stop 整理。按需 lookup/search/read，实质新增才写；写回默认简短回执。当前规范与既有领域路由继续由宿主执行，记忆始终标为历史资料。

旧严格协议显式 --mode strict 保留；升级必须重新 setup 同步 service/hooks。数据、历史、证据、绑定和待判断事项不改。清洗仍需预览及新确认。自动回归不证明 GLM 的规范遵循，需 HOST_TRIAL.md 实战。

## 历史版本记录

# v0.2.0：记忆质量与上下文使用

- 案例和假设写入要求未来用途、反向筛选、适用范围、边界及真实来源。症状线索可参与检索，临时内容可明确到期。
- 新增 memory_context：宿主结合当前项目与会话组织查找，分页目录、全文阅读凭证和当前版本检查；不宣称提供了向量语义检索。
- setup 启用上下文 hook；普通回合不额外续跑，只有通过价值筛选的候选才触发一次 Stop 整理。遗漏筛选留诊断，不假装语义已覆盖。
- 重复内容可复用并登记回执，不增加案例、正文版本或下游复查负担。
- 新增 memory_cleanup：按项目默认每100次知识写入触发只读检查，可用自然语言让宿主配置次数、单次/重复、关闭或稍后。原始事件/重试/复用不计数。
- 清洗先展示预览，应用/撤销要求预览后的新用户确认来源。独立管理账、事务版本校验和执行前备份；原文历史不永久删除。
- 支持归档、明确整体替代、展示摘要提炼和 needs_review 分页复查；旧条目可追踪现行替代项。
- 安装新增项目绑定验收说明，setup 返回 binding_verified，doctor 可核对实际项目、scope、数据目录与上下文 handlers；未绑定不再静默回退。
- 分发程序新增 build-info 报告源码提交，便于核对 GitHub、安装包与实际程序。
- 数据库升级为 v3。打开前先停止旧实例并备份完整数据目录；旧程序不能打开 v3。升级后需重新 setup、重启并验证真实宿主事件。
- 自动化测试包含真实可执行程序的协议/机制回归，宿主语义选择由测试模拟；真实 GLM 预防错误的效果仍需实战验证。

# v0.1.5：ZCode 自动整理后重显业务答复

- 保留 `--review-on-stop`。宿主写入案例回执后读取已保存的业务答复，将正文原样作为续跑的最终输出。
- 续跑结束时对照原答复，诊断记录逐字一致、内容不同或无法比对。比对结果不会触发额外续跑。
- 原版 Windows ZCode 3.16.3 实测，报告正文在聊天底部展开，整理执行一次，保存了一个案例并返回 `reviewed`，答复比对为 `answer_replay_verified`。
- 报告重显由宿主模型执行。ZCode 仍可能折叠原来的消息，最终答复显示重显的正文。
- 本版只更新 memory-mcp。沿用已有 ZCode 登录、测试或正式项目绑定和 SQLite 数据库。升级后重新启动客户端或新建会话以加载新配置。

# v0.1.4：宿主使用与沉淀提示、回执边界修复

- 读取侧提示宿主结合当前任务，将适用且有来源支持的用户明确约定落实到已有工作安排和实际产物；不以“已检索/已阅读”代替实际应用。
- 沉淀侧先查已有全文及当前修订，再决定新建、修订或跳过；仅修订同作用域的当前 case。只有 record/hypothesis 等资料且需要案例时，允许引用可用资料创建首个 case，不转换原类型。
- 回执前检查已关联本轮原文的当前案例，复用 Stop 前已保存的案例 ID。已有同项目当前关联案例时，程序拒绝空回执并返回可补交的 ID，不把本轮误记为 skipped；已完成的历史回执保持不变。
- 明确仅成功的 hook 采集或显式 record 写入才保留原话，stdio 本身不采集聊天；统一 case_ids 与 note 的说明。
- 新增 linked_case_receipts 能力标记与临时库边界检查；程序行为由模拟宿主复现，提示效果不等于真实模型已正确使用记忆。
- 从 v0.1.3 升级时数据库仍为 schema v2，原数据直接复用。升级前停止旧实例并备份数据目录和客户端配置，替换程序后按宿主要求重启或新建会话。
- 提供 Windows amd64、Linux amd64/arm64、macOS amd64/arm64 离线包、源码包及 SHA256SUMS。

# v0.1.3：业务记忆 hooks、资源检索与中文完整性修复

- 提供通用宿主接入入口，首个内置 ZCode 适配器支持用户级 setup/hook/doctor；备份复用已有配置与数据，不修改项目规则。
- 用户输入时检索业务主题，写入工具前结合文件/类名补查；交付真实命中原因、原文片段和全文入口，由宿主核对当前代码与原始规约。
- 回合结束最多请求一次宿主模型整理决策或纠偏，保留原话、项目范围、不可变修订历史及保存/跳过回执。
- 修复损坏 UTF-8 参数被解码器替换后落盘的问题；正文和回执 note 默认拒绝可疑乱码，增加 note 字节数、校验和及旧数据只读诊断。
- 包含 Windows amd64、Linux amd64/arm64、macOS amd64/arm64 离线程序、源码包和 SHA256SUMS；不需要独立模型密钥。
- 升级前关闭使用同一库的旧实例并备份数据目录及客户端配置，更新后重启宿主或新建会话。已有乱码需核对原始材料后修订，不自动猜测还原；数据库核心 schema 保持 v2。
- 自动化测试覆盖实际程序通信与打包流程；其他宿主的 hook 能力以及真实客户端的业务效果按接入步骤单独验证。

# 0.1.3-rc.3：资源线索、命中依据与文本完整性

- 每条交付材料显示实际匹配的词或资源及所在字段；依据变化时允许再次交付，同依据不重复。材料明确作为 guidance，现状和规范由宿主核实。

- doctor --check-text 只读检查旧记录与 note，不猜测恢复丢字。详见 TEXT_INTEGRITY.md。

# 0.1.3-rc.1：首个 ZCode 业务决策与纠偏 hook 候选

- 新增原生 Go `setup`、`hook`、`doctor`，无需 Node/Python 或独立模型 Key。
- UserPromptSubmit 自动保存原话并检索当前项目材料；写入新资源前补查并去重交付。
- Stop 最多请求一次宿主模型整理业务案例或纠偏，通过 memory_review_done 留下实际保存或跳过回执；增加一次宿主模型继续执行。
- 原始输入/答复默认不混入日常业务搜索；案例和修订保留原文来源及历史。
- 用户级合并配置、已有数据复用、一致性备份、显式项目绑定和隔离验收服务名；不改项目规则。
- 对并行进程初次切换 SQLite WAL 时的 BUSY 做有限重试。
- Go 与真实本机二进制流程测试模拟了宿主模型操作，不能代替真实 ZCode/Windows 的 Stop 整理与业务效果验收。

# v0.1.2：写入、读取与恢复可靠性

## 升级前先备份

关闭所有使用同一记忆目录的旧进程，复制整个数据目录作为升级前备份。
首次打开时数据库 v1 自动升级到 v2，不改写既有原文和来源。
旧程序不能直接打开 v2；如需回退，必须恢复升级前的 v1 备份。
多个客户端共用一个库时，应一同更新可执行程序。

## 更新内容

- 可选 request_id：相同逻辑写入重试返回原记录，不重复创建；不同内容复用 ID 会报冲突。
- 写入与完整读取回执包含 UTF-8 正文长度和 SHA-256。
- 搜索和入站引用可继续分页，保留项目范围及复查标记。
- 每个数据库连接应用外键、WAL 和 FULL 同步配置，连接更换后仍生效。
- 新增 backup 命令，生成包含历史、来源与重试键的一致性 SQLite 备份。
- 完善 README 的宿主 Agent 接入步骤与能力识别，项目规则文件无需修改。
- 统一版本文件，测试和打包成功后自动创建版本标签与完整 Release。

## 下载与接入

选择 Windows x64、macOS Intel / Apple Silicon、Linux x64 / ARM64 的程序包。
无需 Go、Python、Node.js 或额外模型密钥；校验文件为 SHA256SUMS。
解压后让宿主 Agent 阅读包内 README 完成接入。

完整 hook 自动采集、自动项目路由与内容整理仍未实现；支持的宿主可使用 guide 命令做会话启动软引导。
本版不宣称偏好学习已带来实际效果提升。
