# 0.5.0-host-recall.1

Previously lookup only matched anchor/signal terms and selected up to two cases, although the host supplied a complete task and uncertainty. This version accepts multiple host-generated search perspectives, searches complete recorded features and preserved evidence through a transactional inverted index, combines rankings, explains matched query numbers and paginates without truncating essential conditions.

The host performs semantic extraction and applicability judgment. There is no extra model, embedding dependency, business taxonomy or built-in business workflow. A separate memory_reference_record registers compact references to already-confirmed agreements without inventing failure stories. Seven tools retain a single-copy JSON response.

Selective code challenges remain. Narrow business-tool pre/post adapters can observe stable identifiers and independent features; source observations retain only hashes and a later action must concern the same object. New input, compaction and explicit agent identity isolate bookkeeping. No raw capture, per-turn reminder, generic approval gate, prepare/complete or Stop continuation.

Schema 4 requires a complete backup BEFORE opening the old library. Entry/profile/index writes commit atomically; migration preserves source data and history. Older schema-3 programs require restoring the pre-upgrade backup. Existing maintenance consent and disabled policies remain intact.

No formal Release. Native hook delivery and actual agent consumption remain separate practical acceptance criteria.

Measured on an isolated 12-record Linux fixture with Go 1.26: median synchronous write 5.81 -> 6.23 ms and compatibility lookup 2.16 -> 2.89 ms (0.4 -> 0.5). Serialized tool-directory JSON grows from 10,484 to 13,642 bytes (+3,158); host caching/deferred loading and actual model token impact are not certified. These are fixture measurements, not total-task or cross-machine guarantees.
