# Host reasoning and local recall

Follow current user instructions and project rules. The host understands the full visible task and performs semantic comparison; MCP does not translate natural language, impose business categories, generate embeddings or call another model.

After a correction or autonomous discovery has been investigated, synchronously memory_experience_record the challenged inference, actual counterevidence, concrete impact, future recognition conditions, exceptions and evidence locators. Corrections are signals, not truth. Ordinary facts/progress and unverified explanations do not qualify. Reuse exact equivalents; request_id retries the same payload and previous_id preserves material revisions. Record and index commit atomically. indexed is a storage receipt, not a semantic quality certificate.

Use memory_reference_record only for compact pointers to EXISTING explicitly confirmed agreements. Supply actual authority, confirmation locator, scope and exceptions. Do not copy manuals, invent failures or infer rules from agent output. Indexing an authorized source creates no authority; changes of meaning/scope require the relevant authorization.

For lookup, reconstruct task/questions from the current context. Supply 1-4 queries from different business-object, current-assumption or mechanism perspectives, with grounded terms and match=all (default) or any. Do not stuff synonyms or invent task labels. keywords remains a compatibility single-query input. Task/questions are context supplied by the host, not text the server semantically interprets. The server searches full recorded features, combines lexical rankings and reports matched_queries/matched_terms.

Compare premises and exceptions yourself, then check current code/runtime/business facts. Similar words, receipts and locations prove neither applicability nor permission. Refine queries or follow next_cursor if needed. Changed queries or corpus require restarting pagination. No hit does not prove no risk. Up to three complete items (default two) fit one JSON text body <=8 KiB without slicing conditions. Legacy excerpts are navigation only; memory_read returns their full source. Legacy prose is not silently promoted to a trigger.

Hooks briefly challenge only specific observable code/business features. Use the actual optional challenge_id. Unrelated operations and project-rule reads remain available. Selected business PostToolUse observes source data without injecting case material; only identifier hashes and candidate IDs survive. A later same-object operation may pause. No prompt/tool-result body is persisted.

One native input has one pause budget. Failures/two-minute expiry release without fake completion. Reported compaction invalidates bookkeeping, but receipts do not establish actual model-context visibility. Explicit agent IDs are isolated; missing adapters/native identity and pure text remain coverage limits. Ordinary inputs are silent; there is no Stop continuation.

Maintenance stays separate: inspect/preview a reversible plan, then obtain NEW actual approval for that shown plan before confirm/apply. Undo needs fresh approval. Approval excerpts are hidden from business retrieval. Preserve evidence, history and backups.
