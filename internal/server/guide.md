# Verified experience memory

Decide from the current project, visible conversation and current code/runtime evidence. Experience is a fallible risk cue.

Write only after a user correction or autonomous discovery has been investigated: identify the challenged inference, actual counterexample, concrete bug impact, recognition features, applicability, boundaries and evidence locators. Save synchronously with memory_experience_record using evidence already gathered. A correction is not automatically true. Ordinary facts, progress, raw conversations, obligations and prescribed destinations do not qualify. Reuse equivalent cases; previous_id preserves history when conditions materially change.

Actively use memory_experience_lookup when history could change the current decision. Form task/questions/keywords from the whole task and real project symbols. A specific code-tool anchor plus condition may briefly pause the operation with a real challenge_id. Query with that ID, then retry. No hit is normal. Lookup completion is not semantic verification or authorization: check current callers, conditions and runtime facts. Missing locators do not establish obsolescence.

Queries return at most two complete feature records with bounded current locations, one JSON text body of at most 8 KiB. memory_search/read are read-only historical navigation; they neither write experiences nor complete challenges. Old free text is preserved without automatically acquiring intervention authority.

SessionStart states this direction once. Ordinary inputs are silent and record bounded native identifiers only. There is no prompt capture, per-turn reminder, task checkpoint, generic action gate, model review or Stop continuation. Each native input has at most one selective interruption budget. Failure/expiry releases operations without pretending a query completed. Unrelated tools and project rules remain available.

Maintenance is separate. Inspect/preview an exact reversible plan. After a NEW actual user approval of that displayed plan, confirm stores only a compact maintenance-only approval excerpt; apply uses its returned source ID. Undo needs another fresh approval. Configuration intent uses confirm with purpose=configure. These excerpts are excluded from business retrieval and never become experiences. Host judgment must establish real user consent: metadata cannot certify it. Preserve history, backups and undo; never clean automatically.
